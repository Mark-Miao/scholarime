# Systematic Review Screening

`scholarime screening` adapts the `sr-screener` workflow from Academic Research Skills. Use it only
when the user has a review protocol or eligibility criteria and asks to screen records, resolve
screening conflicts, audit exclusions, or produce PRISMA counts. A request to write a literature
review does not automatically start screening.

## Setup

Create a work directory and customize the copied protocol and configuration:

```bash
scholarime screening init review-screening
```

The configuration must define ordered exclusion codes, core eligibility criteria, reviewer
personas, a conflict policy, QC sampling, and any seed studies. Seed studies are sensitivity checks,
not training examples.

## Prepare Records

Screening accepts RIS, PubMed/MEDLINE, Web of Science, CSV exports, and Scholarime JSON directly:

```bash
scholarime screening prepare \
  --work review-screening \
  --inputs candidates.json \
  --config review-screening/screening_config.json
```

Scholarime JSON is converted to RIS without modifying the source. `candidates.json`,
`citation-verification.json`, and `final_references.json` are supported. Duplicate removal is
auditable, and screening IDs remain stable after decisions begin.

If `--workspace project` is supplied, preparation metadata is recorded as a workspace artifact.

## Blinded Screening

Generate reviewer prompts or a workflow file:

```bash
scholarime screening workflow ta \
  --work review-screening \
  --protocol review-screening/screening_protocol.md \
  --config review-screening/screening_config.json \
  --jobs pilot \
  --emit-prompts review-screening/prompts
```

Use separate reviewer contexts. Reviewer A and Reviewer B receive the same protocol and must not see
each other's decisions. A third context adjudicates disagreements. A separate QC reviewer checks
required joint exclusions.

```bash
scholarime screening merge \
  --work review-screening \
  --from review-screening/decisions-a.json review-screening/decisions-b.json \
  --stage ta
```

Pass the exact files generated by the bundled workflow. Do not invent reviewer decisions or fill
pending records by default.

## Outputs

```bash
scholarime screening outputs \
  --work review-screening \
  --out review-output \
  --stage ta \
  --workspace project
```

The command writes the screening log, RIS groups, PRISMA counts, methods draft, and
`TA_scholarime_sources.json`. When `--workspace project` is supplied, the selected sources are
imported or updated automatically and the screening reports are recorded as artifacts. The JSON
remains available for explicit import with
`scholarime workspace add-sources project review-output/TA_scholarime_sources.json`.

AI screening is decision support. The review team must verify advanced studies, exclusions,
adjudications, and every number used in the manuscript. PRISMA output is provisional until pending
records and required QC rechecks are resolved.
